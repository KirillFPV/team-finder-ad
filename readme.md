# TeamFinder — вариант 2

Платформа поиска команды для pet-проектов. Реализованы регистрация и вход по email,
публичные профили, редактирование профиля и аватара, смена пароля, проекты и участие
в них, админка, навыки пользователей и фильтрация участников по навыку.
Списки проектов и пользователей разбиты на страницы по 12 элементов.

## Требования

- Python 3.13 (на этой версии проект проверен).
- Docker Desktop / Docker Engine с Docker Compose.
- Свободные локальные порты 8000 и 5436.

Используется PostgreSQL 16 в контейнере; SQLite не используется.
Django обновлён внутри ветки 5.2 до
[релиза 5.2.18 с исправлениями безопасности](https://www.djangoproject.com/weblog/2026/oct/06/security-releases/).

## Запуск

Команды выполнять из корня проекта. Если `.venv` уже создано, пропустите команду
создания. Активируйте окружение в каждой новой сессии терминала.

```bash
python3.13 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env_example .env
```

В `.env` замените `DJANGO_SECRET_KEY` и `POSTGRES_PASSWORD` своими значениями.
Секретный ключ можно получить командой:

```bash
python -c 'from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())'
```

Параметры по умолчанию: БД `team_finder`, пользователь `team_finder`, хост `localhost`,
порт `5436`. Compose использует тот же внешний порт из `.env`, внутри контейнера
PostgreSQL слушает 5432. Если внешний порт занят, измените `POSTGRES_PORT` в `.env`.
Поле `TASK_VERSION=2` оставлено для обозначения варианта; приложение использует
только `templates_var2`.

```bash
docker compose up -d --wait
python manage.py migrate
python manage.py createsuperuser
DEMO_PASSWORD=TeamFinder-demo-2026 python manage.py seed_demo
python manage.py runserver 127.0.0.1:8000
```

Открыть [TeamFinder](http://127.0.0.1:8000/) и [админку](http://127.0.0.1:8000/admin/).
Администратора создаёт команда `createsuperuser`: задайте email, имя, фамилию и пароль.
На Windows переменную `DEMO_PASSWORD` можно задать через `$env:DEMO_PASSWORD` в PowerShell.

Команда `seed_demo` создаёт следующие учебные аккаунты с паролем из `DEMO_PASSWORD`:

| Email | Пользователь |
| --- | --- |
| anna@example.com | Анна Иванова |
| ivan@example.com | Иван Петров |
| maria@example.com | Мария Смирнова |

У каждого есть навыки и собственный проект. Команду можно повторять: она не создаёт
дубликаты и не меняет пароли уже существующих аккаунтов. Эти данные предназначены
для локальной проверки. `.env`, загруженные изображения и окружение исключены из Git.

Остановка БД без удаления данных:

```bash
docker compose down
```

Данные хранятся в именованном volume `postgres_data` и сохраняются при обычной
остановке и перезапуске контейнера. Изменение пароля PostgreSQL в `.env` после
инициализации volume само по себе не изменяет пароль роли внутри существующей БД.

## Проверки

Запустите PostgreSQL и установите зависимости для разработки:

```bash
python -m pip install -r requirements-dev.txt
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test --noinput
ruff check .
ruff format --check .
```

Тесты создают отдельную базу `test_team_finder` в PostgreSQL, основную базу не очищают.
Для другого имени БД используется префикс `test_`. Учётная запись БД должна иметь
право создания тестовой базы (пользователь из Compose его имеет).

Тесты проверяют аутентификацию, блокировку аккаунта, права владельца, смену пароля,
аватары, email/телефон/GitHub, проекты, участие, навыки, CSRF, пагинацию, фильтрацию,
админку и повторную загрузку демоданных.

Ручной сценарий для варианта 2:

1. Войти как Анна, открыть свой профиль и добавить существующий навык через подсказку.
2. Ввести новый навык, выбрать «Создать», затем удалить тег. Страница не перезагружается.
3. Открыть «Участники», выбрать тег; проверить подсветку и «Сбросить».
4. Открыть чужой профиль: кнопок изменения навыков быть не должно.
5. Создать проект, войти как Иван, присоединиться к проекту и отказаться от участия.
6. Войти как автор, изменить и завершить проект. Новое участие в закрытом проекте недоступно.
7. Проверить загрузку аватара и номер телефона в форматах `8XXXXXXXXXX` / `+7XXXXXXXXXX`.
8. Выйти и проверить, что проекты, профили и фильтры доступны гостю, а изменения требуют входа.

## Маршруты и JSON

- `/` → `/projects/list/`; `/project/list/` — совместимый редирект на тот же список.
- `/users/register/`, `/users/login/`, `/users/logout/` (POST).
- `/users/list/?skill=Python&page=2`, `/users/<id>/`.
- `/users/edit-profile/`, `/users/change-password/`.
- `/projects/create-project/`, `/projects/<id>/`, `/projects/<id>/edit/`.
- POST `/projects/<id>/complete/` → `status`, `project_status`.
- POST `/projects/<id>/toggle-participate/` → `status`, `participant`.
- GET `/users/skills/?q=Py` → до 10 объектов `{id, name}`, поиск по началу названия.
- POST `/users/<id>/skills/add/` с JSON `{"skill_id": 1}` либо `{"name": "Django"}`
  → `skill_id`, `id`, `name`, `created`, `added`.
- POST `/users/<id>/skills/<skill_id>/remove/` → `status`, `removed`.

Изменяющие запросы защищены сессией, CSRF и проверками прав на сервере.
Для JSON-запросов нужны cookie сессии и заголовок `X-CSRFToken`.

## Решения по неоднозначностям задания

- `User.skills` — ManyToMany с обратной связью `Skill.users`: один пользователь может
  владеть несколькими навыками. Указание ForeignKey в рекомендациях противоречит UI.
- Обязательные поля регистрации — имя, фамилия, email и пароль. Аватар с первой буквой
  имени генерируется автоматически. Телефон необязателен; заполненный номер приводится
  к `+7XXXXXXXXXX`, уникальность проверяется после нормализации и обеспечивается БД.
- В форму редактирования добавлен email, как требует функциональное описание.
- Email и названия навыков уникальны без учёта регистра. Пробелы вокруг навыка убираются.
  Сам фильтр `?skill=` использует точное совпадение названия, как в условии.
- Пользователи и проекты отображаются от новых к старым; контекст списков дополнен
  `page_obj` и `query_prefix`, которые используют готовые шаблоны.
- Ответ добавления навыка расширен `id` и `name` для совместимости с исходным JS.
- «Избранное» реализуется в варианте 1 согласно разделу вариативности и спецификации
  endpoints. Вариант 2 использует навыки пользователей; повторения избранного в общем
  описании не перенесены в этот вариант. Шаблоны вариантов 1 и 3 сохранены как исходные материалы.
- Выход сделан POST-запросом с CSRF вместо предложенного GET. Остальные изменения
  состояния также используют POST. Ссылки и запросы приведены к завершающему `/`.
- Автор включается в участников автоматически и не может отказаться от собственного
  проекта. После закрытия новое участие запрещено, уже вступившие могут выйти.
- Список проектов показывает также закрытые проекты со статусом. Изменение статуса
  не удаляет проект и публичную страницу.
- Исправлена безопасная вставка названий навыков, обработка ошибок и устаревших подсказок,
  сохранение фильтра при пагинации и кнопки создания для гостей.
- Администратор управляет любыми пользователями, навыками и проектами через `/admin/`.
  Обычные страницы изменения доступны владельцам.

## Структура

- `users/` — пользователь, навыки, формы, JSON endpoints, админка и `seed_demo`.
- `projects/` — проекты, формы, участие, админка.
- `team_finder/` — настройки, общие валидаторы и HTTP-декоратор.
- `templates_var2/`, `static/` — интерфейс варианта 2.
- `tests/` — интеграционные тесты на PostgreSQL.
- `docs/` — исходные материалы и план реализации.

Локальный сервер Django и `DJANGO_DEBUG=True` предназначены для разработки. Для
публикации нужны отдельные production-настройки, WSGI/ASGI-сервер, HTTPS и раздача
статики/media. Публикация и отправка задания на платформу в локальный запуск не входят.
